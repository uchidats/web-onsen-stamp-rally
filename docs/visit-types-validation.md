# 訪問形態の検証（2026-10-21）

## 実装とデータ保護

- 任意の `visitType`（`day` / `stay`）を訪問ごとに追加。項目なし・空文字は未設定。既存ID・日付・メモ・保存キー・v3バックアップ形式は維持。既存Firestore文書の一括移行・書き換えは行わない。
- 同じ施設の複数訪問を個別に保存・編集。施設マスター、施設単位の達成度は変更しない。
- 日付・メモと独立して比較し、異なる形態の同時変更は両案を保持して選択する。入力中の他端末更新も検出して保存を拒否する。
- Rulesは任意の列挙値のみ追加許可。本人制限・revision・世代ID・削除制約を維持。旧クライアントのpartial updateが形態を消さないことも検証。
