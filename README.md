# 湯めぐり図鑑

67施設の公開情報と利用者個人の記録を分離した静的サイトです。公開時は `index.html`、`data.js`、`records.js`、`app.js` を配置してください。Googleログイン・Firebaseは未実装です。

## 保存と施設ID

新規利用者は訪問済み0件から開始します。訪問チェックはブラウザのlocalStorageへ自動保存され、全体・都道府県別の達成率、訪問状態フィルターに反映されます。ブラウザや公開URLが変わると記録を自動では引き継げません。変更前にバックアップしてください。

67施設のIDは固定です。施設の追加・編集・並べ替えで既存IDを変更したり、削除したIDを別施設に再利用したりしないでください。

公開マスターには訪問日・訪問回数・訪問状態・個人メモ・個人の好みを含めません。施設情報は訪問前に公式情報で確認してください。

## バックアップと旧版からの移行

「記録をバックアップ」で個人データをJSONへ保存し、「記録を復元」で読み込みます。復元前の記録はブラウザ内へ退避します。バックアップには個人情報が含まれるため、公開フォルダやGitへ入れず個人用の場所に保管してください。

旧版は45施設をマスターから訪問済みとし、旧localStorageと旧バックアップにはチェック変更分のみ保存していました。旧バックアップ単独では元の45施設を再現できません。

旧版の所有者は、別途保護した個人用移行JSONを使用してください。サイトに移行用JSONは同梱していません。

1. 旧版と同じブラウザ・同じ公開URLで「記録を復元」から個人用移行JSONを選ぶ。
2. 確認後、元の訪問記録に旧localStorageの変更分を反映して新保存領域に保存する。旧領域は削除しない。
3. 旧版で書き出したバックアップを使う場合は、移行用JSONの復元後に旧バックアップを復元する。
4. 新しいバックアップをダウンロードして保管する。

個人の好みによる旧分類は公開マスターから除外しています。対応情報を含む個人用移行JSONでは `favoriteOnsenIds` として保護しています。今回、個人ランキングやお気に入りの画面は実装していません。

## 将来の拡張

`records.js` が保存・検証・復元を担当します。将来はこの保存層を認証済みユーザーのFirestore保存へ差し替えられます。個人データには `visits`、`rankings`、`rankingVisibility`（既定private）、`gpsStamps` を設けています。Googleログイン、クラウド同期、ランキング、GPS機能の追加時には、UIDごとのアクセス制御を実装してください。

## 検証と公開

`node tests/records.test.cjs` で新規0件、保存・再読込、都道府県別集計、フィルター、バックアップ復元、旧45施設の移行、異常データ拒否、退避、保存失敗保護を検証します。通常は架空のテストデータを使用します。実移行データの検証はGit管理外ファイルのパスを `ONSEN_PRIVATE_MIGRATION_FILE` に指定します。

GitHub Pagesではmainのルートを公開元とし、`_config.yml` でドキュメントとテストを配信対象から除外します。個人用ファイルの誤追加を `.gitignore` で防ぎますが、既存Git履歴からの削除やデプロイ先へのコピー防止は別途確認が必要です。
