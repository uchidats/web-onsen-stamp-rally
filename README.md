# 温泉の旅（My Onsen Journey）

67施設の公開情報と利用者個人の記録を分離した静的サイトです。公開時はHTML、CSS、JavaScript（`analytics.js`を含む）と `vendor/`・`assets/` を配置してください。Googleログイン・Firebaseは未実装です。

GA4は公開URLでアクセス解析に同意した場合だけ読み込みます。ローカルでは計測しません。公開前のGA4拡張計測設定・同意・検証の手順は[analytics.md](docs/analytics.md)を参照してください。

## 保存と施設ID

新規利用者は訪問済み0件から開始します。訪問チェックはブラウザのlocalStorageへ自動保存され、全体・都道府県別の達成率、訪問状態フィルターに反映されます。ブラウザや公開URLが変わると記録を自動では引き継げません。変更前にバックアップしてください。

詳細画面の「訪問記録」から、訪問日を追加・編集・削除できます。日付ピッカーを使用し、一覧は新しい日付順、日付不明は末尾に表示します。訪問ごとに固有IDを持ち、同日の複数訪問も別の記録として保存します。「日付不明」も1回の訪問です。訪問回数は記録件数から、達成率は記録を1件以上持つ施設数から計算します。日付付き記録や複数の記録がある施設のチェックを押すと、詳細の編集画面へ進みます。

67施設のIDは固定です。施設の追加・編集・並べ替えで既存IDを変更したり、削除したIDを別施設に再利用したりしないでください。

公開マスターには訪問日・訪問回数・訪問状態・個人メモ・個人の好みを含めません。施設情報は訪問前に公式情報で確認してください。

## バックアップと旧版からの移行

「記録をバックアップ」で個人データをJSONへ保存し、「記録を復元」で読み込みます。復元前の記録はブラウザ内へ退避します。バックアップには個人情報が含まれるため、公開フォルダやGitへ入れず個人用の場所に保管してください。

複数訪問版は `onsen-rally-user-v3` とバックアップ形式 `onsen-stamp-rally-v3` を使用します。従来の `onsen-rally-user-v2` と `onsen-rally-visits-v1` は削除しません。旧記録は読み取り時にメモリ内で変換し、画面の「移行前の記録を保存」で元の保存文字列をそのままダウンロードできます。「記録を移行する」の確認後にのみ新領域へ保存し、ブラウザ内にも `onsen-rally-before-migration-v3` として元データを退避します。確認をキャンセルした場合は保存しません。退避に失敗した場合も移行・復元を進めません。

v2バックアップ、v1の変更分バックアップ、移行前の生データバックアップも復元できます。復元は毎回確認し、直前のv3記録を `onsen-rally-before-restore-v3` に退避します。v1変更分だけでは元の45施設を推測せず、従来どおり個人用移行JSONの `legacyBaseline` が必要です。v1の保存領域だけがある場合は、明示されたチェック情報のみを日付不明の記録へ変換します。

旧データの訪問回数、初回日、最終日、および `visitDates` / `dates` の日付一覧を引き継ぎます。初回・最終日と一覧の重複は二重計上せず、一覧にある同日の複数訪問は保持します。記録された回数が日付件数より多ければ不足分を日付不明にします。判読できない日付は `legacyDate`、旧施設情報は `legacyVisitInfo` として残し、架空の日付を作りません。日付情報または正の訪問回数がある場合は旧フラグがfalseでも訪問履歴を保持し、記録件数に基づいて訪問済みと判定します。最終訪問日は判明している日付の最大値で、日付不明の件数も併記します。別のタブが更新した記録を古い状態で上書きしようとした場合は保存を中止します。

旧版は45施設をマスターから訪問済みとし、旧localStorageと旧バックアップにはチェック変更分のみ保存していました。旧バックアップ単独では元の45施設を再現できません。

旧版の所有者は、別途保護した個人用移行JSONを使用してください。サイトに移行用JSONは同梱していません。

1. 旧版と同じブラウザ・同じ公開URLで「記録を復元」から個人用移行JSONを選ぶ。
2. 確認後、元の訪問記録に旧localStorageの変更分を反映して新保存領域に保存する。旧領域は削除しない。
3. 旧版で書き出したバックアップを使う場合は、移行用JSONの復元後に旧バックアップを復元する。
4. 新しいバックアップをダウンロードして保管する。

個人の好みによる旧分類は公開マスターから除外しています。対応情報を含む個人用移行JSONでは `favoriteOnsenIds` として保護しています。今回、個人ランキングやお気に入りの画面は実装していません。

## 将来の拡張

マイページの名称は「私の温泉」、個人ランキング機能の名称は「私の名湯ランキング」を予定しています。今回は名称の整理のみで、これらの画面・機能は実装していません。

`records.js` が保存・検証・復元を担当します。将来はこの保存層を認証済みユーザーのFirestore保存へ差し替えられます。個人データには `visits`、`rankings`、`rankingVisibility`（既定private）、`gpsStamps` を設けています。Googleログイン、クラウド同期、ランキング、GPS機能の追加時には、UIDごとのアクセス制御を実装してください。

v3の `userData.visits[温泉固定ID].records` は訪問ごとの配列です。各記録に `id`、`date`（YYYY-MM-DDまたはnull）、`notes`、`photos`、`gpsStamp` を用意しています。施設単位の `notes` と既存の個人設定も保持します。`visited`、`visitCount`、`firstVisit`、`lastVisit`、`unknownCount` は配列から再計算する派生値です。将来はユーザーUIDの下で訪問IDをクラウドの文書IDに使い、写真参照やGPS認証情報を追加できます。認証・同期・写真・GPS・CSV／Excel出力は今回は実装していません。

## 検証と公開

`node tests/records.test.cjs` で新規0件、保存・再読込、都道府県別集計、フィルター、バックアップ復元、旧45施設の移行、異常データ拒否、退避、保存失敗保護を検証します。通常は架空のテストデータを使用します。実移行データの検証はGit管理外ファイルのパスを `ONSEN_PRIVATE_MIGRATION_FILE` に指定します。

`node tests/multiple-visits.test.cjs` で複数訪問の追加・編集・削除、日付と回数、日付不明の保持、確認を伴う移行、元データの保護、保存失敗、複数タブの更新競合を検証します。`node tests/official-links.test.cjs` は施設リンクと67施設の固定IDを検証します。

GitHub Pagesではmainのルートを公開元とし、`_config.yml` でドキュメントとテストを配信対象から除外します。個人用ファイルの誤追加を `.gitignore` で防ぎますが、既存Git履歴からの削除やデプロイ先へのコピー防止は別途確認が必要です。
